Principles

What a modern company needs from a design system — and how Boxed DS answers.

One source of truth

Colors, type, space, and motion live as CSS custom properties. Change a token once; product UI updates everywhere.

Ship-ready components

Buttons through tables, modals, toasts, and empty states — with states (hover, focus, disabled, loading, error) built in.

Accessible by default

Focus rings, keyboard navigation, ARIA roles, reduced-motion support, and skip links. WCAG-minded contrast in both themes.

Zero-build friendly

Plain HTML, CSS, and JS. Drop into marketing sites, internal tools, or migrate pieces into React/Vue later via the same class API.

Dark & light themes

Semantic tokens remap per theme. Brand accent stays identity-strong in dark mode; slightly deepened for light-mode contrast.

Progressive JS

Theme, modal, dropdown, tabs, accordion, toast, and copy work via data-bx-* attributes. No framework required.

Usage

Include the system once. Prefer semantic tokens over hard-coded colors.

HTML 
<html data-theme="dark">
  <link rel="stylesheet" href="design-system/css/design-system.css">
  <script src="design-system/js/design-system.js" defer></script>
  <button class="bx-btn bx-btn--primary">Request Specs</button>
</html>
Class prefix: all public classes use bx-. Interactive hooks use data-bx-*. Docs chrome uses ds- and is not for product use.

Accessibility

Non-negotiables for a company-grade system.

  • Visible :focus-visible rings on all interactive controls
  • Skip link to main content
  • Modal focus restore + Escape to close
  • Tabs: arrow key navigation, aria-selected, panel association
  • Toasts use aria-live; errors use role="alert"
  • prefers-reduced-motion zeros animation durations
  • Form fields: labels, required indicators, error text tied to invalid state
  • Icon-only buttons require aria-label
  • Color is never the only status signal (dots + labels)
