LOG_ID: 2026-07-25 · AMERICAMATTER / CINEMATIC · WEBGPU

Film that seeks with the scroll

Notes from americamattercorp/cinematic — matte-paint aerospace industrial UI, WebGPU depth heroes, and a scroll stage that drives video by seeking, not by playing.

WebGPUScroll scrubDepth mapReduced motion

01 · What it is

A separate direction from the paper CNC catalog: void blacks, sky blues, assembly-tower imagery. Landing variants swap between WebGPU depth, looping hero film, and scroll-scrub film.

02 · Why seek, not play

Scroll scrub never “plays” the media timeline. Progress is mapped into video.currentTime. The film becomes a scrubbable document — beats of copy can land on frames instead of fighting autoplay policies.

03 · Scrub asset recipe

# every frame is a keyframe so seeks land cleanly
ffmpeg -y -i images/hero.mp4 -an -c:v libx264 -preset medium -crf 20 \
  -g 1 -keyint_min 1 -sc_threshold 0 -bf 0 -pix_fmt yuv420p \
  -movflags +faststart images/hero-scrub.mp4

// runtime: lerp scroll progress → currentTime, wait for seeked

04 · Hero stack

  • Color plate + greyscale depth map
  • WebGPU color + depth effects when available
  • Secure context required (local server, not file://)
  • Video loop / poster fallbacks

05 · Motion a11y

prefers-reduced-motion: hero-video shows poster only; scroll-video falls back to a simple muted loop. Spectacle never overrides the system setting.

Design bias

Cinematic UI is a different contract from print catalogs. Keep them in separate packages so navy paper stock and void-sky matte paint never fight for the same tokens.

Takeaway

Build film as data: all-intra encodes, sticky scroll stages, lerped seeks. Pair WebGPU depth when the machine allows; always ship a video and still path. Related print surface: CNC Metal Vol. 1.
