Cross-document view transitions

How this site wipes left-to-right between pages without intercepting navigation, covering the screen, then animating after load.

@view-transitionpageswappagerevealclip-path wipe

01 · The wrong pattern

Canvas cover → location.href → canvas reveal feels like two loads. The wipe is not the navigation; it is a pre- and post-animation around a hard reload.

02 · The right API

Cross-Document View Transitions let the browser snapshot old and new documents during a same-origin navigation. Opt in on every page; animate ::view-transition-new(root).

03 · Opt-in + wipe

/* style.css — both documents */
@view-transition { navigation: auto; }

::view-transition-new(root) {
  animation: 600ms cubic-bezier(0.22, 1, 0.36, 1) both vt-wipe-ltr;
  z-index: 2;
}

@keyframes vt-wipe-ltr {
  from { clip-path: inset(0 100% 0 0); }
  to   { clip-path: inset(0 0 0 0); }
}

04 · Direction types

  • data-page-transition="ltr|rtl" on links
  • Click stores direction (no preventDefault)
  • pageswap / pagereveal add types
  • Script in <head> so pagereveal is heard

05 · Constraints

  • Same-origin only
  • Chromium-class browsers first
  • HTTP(S), not file://
  • prefers-reduced-motion: navigation: none
Design bias

Let the browser own navigation. Your job is CSS keyframes and a tiny direction helper — not a second rendering engine between clicks.

Takeaway

Files: style.css (opt-in + wipe), page-transition.js (types). Every blog and case-study page loads both. Click 04_BLOG from home to feel the contract.
