Hard edges, scroll blinds, and a system that stays boxed

Notes from shipping Boxed Systems: a tech-brutalist marketing demo (horizontal blinds + GSAP/Lenis) and a zero-build company design system under the same brand language.

Hydro-ModuleMyco-ModuleCryo-Module

01 · What it is

Boxed Systems is two surfaces that share one visual contract: a scroll-driven marketing stage (module imagery revealed through horizontal blinds) and a living style guide that product UI can consume without a bundler.

Brand constants stay loud and simple — teal (greenbox), yellow (yellowbox), ink blacks, solid faces, radius zero.

02 · Why brutalism here

Soft chrome and pill UI fight hardware/product storytelling. Hard edges read as specification sheets: one primary action, contrast blocks, focus rings you can actually see.

The marketing site can use motion (blinds, smooth scroll). The design system stays progressive and boring where it counts — forms, modals, tables, theme toggle.

03 · Repo shape

// Boxed-Systems/
index.html                 # marketing + blinds demo
css/ · js/ · img/
design-system/
  index.html               # living style guide
  css/tokens.css           # foundations
  css/components.css       # bx-* library
  js/design-system.js      # BoxedDS API

04 · Class contract

  • bx- — ship in product
  • data-bx-* — progressive hooks
  • ds- — docs chrome only

Tokens first: no hard-coded brand hex inside components. Theme via data-theme on <html>.

05 · Runtime API

BoxedDS.theme.set('dark')
BoxedDS.toast({ title: 'Saved', variant: 'success' })
BoxedDS.modal.open('request-specs')

06 · Design principles (ship rules)

  1. Tokens first — semantic variables, not one-off hex.
  2. Hard edges — surface radius is 0; no soft pill chrome.
  3. Solid faces — contrast blocks over decorative blur.
  4. One primary action per view (Request Specs, not five CTAs).
  5. Accessible defaults — rectangular focus, keyboard paths, reduced motion.
  6. Zero-build — plain CSS/JS; lift the class API into React later if needed.
  7. Brand continuity — same teal/yellow/ink as the blinds demo.

Design bias

Motion and spectacle on the marketing stage; tokens, components, and a tiny JS API in the design system. Both stay constrained, named, and reusable — no new gray for every screen.

Takeaway

The interesting split is intentional: motion and spectacle on the marketing stage; tokens, components, and a tiny JS API in the design system. Both stay “boxed” — constrained, named, and ready to reuse without inventing a new gray for every screen.
