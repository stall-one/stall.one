Pair the desktop. Mount the vault.

How TaxFort gets files in without the browser UI: inbound webhooks to a vault inbox, and a Tauri desktop client that pairs to a user then mounts org-scoped storage with STS.

Desktop pairingSTSWebhooksJuiceFS S3

01 · Two entry paths

Webhooks — email / SMS / storage events land objects under an org prefix inbox. No browser JWT; secrets and event identity resolve the vault.

Desktop pairing — device starts a pair flow, web confirms, auth issues device binding. Vault then hands short-lived STS for a local mount.

02 · What pairing is not

Pairing does not transfer workspace ownership or decide who pays (firm pool vs client pays). It only binds a device to a user. Billing and membership stay elsewhere.

03 · Topology sketch

04 · Design surface

  • Soft purple SaaS chrome (taxBox Safe)
  • Pairing code as a large, scannable artifact
  • Desktop “Z: drive” metaphor for mount success
  • Same identity headers as browser after pair

05 · Storage notify

JuiceFS S3 gateway fires into the Docker network DNS name of the gateway — never localhost from inside the container. Secret lives on vault-service.

Design bias

Accountants live in the filesystem. Pairing + STS keeps the same tenancy rules as the web vault while meeting them where they work — without turning every laptop into a long-lived secret store.
