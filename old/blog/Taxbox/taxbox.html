Multi-tenant vaults where isolation is the product.

Notes from shipping TaxFort inside the taxbox tree: gateway-fronted microservices, org-scoped JuiceFS storage, firm vs client billing, and a desktop path that mounts credentials without turning every laptop into a secret store.

API GatewayBetter AuthStripeJuiceFS S3Valkey ×2Tauri

01 · What taxbox is

Taxbox is the working tree for TaxFort: landing surfaces, dashboard UX, a desktop companion, and the self-contained taxfort-platform microservices stack.

Product job: let firms run document vaults for tax workflows where tenancy, entitlement, and storage paths are enforced by services — not by “please don’t click the wrong folder.”

02 · Why the split

Auth owns identity and workspaces. Billing owns paid state. Vault owns “may this org touch this prefix?” Storage (JuiceFS S3 gateway) stays dumb and durable. The gateway is the only public front door.

That split keeps a compliance-shaped problem from collapsing into one god service with accidental cross-tenant joins.

03 · Topology

Browser / Vite web
        │
        ▼
api-gateway          # JWT / API key, rate-limit, identity headers
   ├── auth-service     # sessions, orgs, members, desktop pairing
   ├── billing-service  # Stripe, plans, entitlements
   └── vault-service    # S3 presign + STS under orgs/{id}/
              │
              ▼
         Postgres  +  JuiceFS S3 gateway
         Valkey: gateway rate-limit · agent inbox queue

04 · Service ownership

Service One line
api-gateway Route + verify at the edge; inject identity headers; strip bearer after check
auth-service Who you are + workspaces + roles + invites + desktop pairing
billing-service Stripe + subscriptions + entitlements (firm pool vs Client Pays)
vault-service If member + entitled → presign / STS under orgs/{id}/

05 · Isolation rules

  • Membership checked before vault ops
  • Object keys namespaced by organization id
  • Gateway is the browser trust boundary
  • Downstream trusts injected headers, not raw client JWT reuse

06 · Desktop & webhooks

Tauri pairs to the web session, then receives short-lived STS for a local JuiceFS mount — so accountants can live in the filesystem, not only a browser dropzone.

Inbound webhooks (email / SMS / storage) land in vault inbox paths for agent classification without a free-for-all upload hole.

Takeaway

Taxbox is the engineering sandbox that became TaxFort’s platform: microservices with clear ownership, JuiceFS for durable blobs, dual Valkey for edge vs agent queues, and a desktop path that doesn’t abandon the same auth model.
